# 2장. 컨텍스트는 공짜가 아니다

지침 파일을 작성할 때 가장 위험한 가정은 “도움이 될 것 같으면 일단 넣자”다.

항상 로드되는 지침은 공짜가 아니다. 토큰을 소비하고, 모델의 주의를 분산시키며, 서로 관련 없는 규칙이 같은 작업에 간섭할 수 있다.

## 2.1 상시 컨텍스트의 세 가지 비용

첫째는 직접 비용이다. 입력 토큰과 처리 시간이 증가한다.

둘째는 주의 비용이다. 중요한 작업 정보와 오래된 지침이 같은 컨텍스트에서 경쟁한다.

셋째는 행동 비용이다. 모델이 필요하지 않은 검증, 검색, 확인 절차를 수행할 수 있다.

특히 “항상”, “반드시”, “모든 작업에서” 같은 표현은 의도보다 훨씬 넓은 행동 변화를 만들 수 있다.

## 2.2 긴 지침보다 더 위험한 것

문서 길이 자체가 품질을 결정하지는 않는다. 짧아도 잘못된 위치에 있으면 문제다.

릴리스 절차가 30줄밖에 되지 않더라도 모든 코드 수정에서 읽힌다면 불필요한 컨텍스트다. 반대로 특정 Skill이 300줄이어도 실제 릴리스 요청에서만 로드되고 필요한 절차를 정확히 제공한다면 더 합리적일 수 있다.

따라서 200줄 이하, 500줄 이하 같은 수치는 hard rule이 아니라 리팩터링 신호로 보는 편이 낫다.

## 2.3 Instruction Debt

코드에 기술 부채가 있듯 지침에도 부채가 생긴다.

과거 모델이 자주 놓치던 행동을 보완한 규칙, 한 번의 장애에 과도하게 대응한 경고, 더 이상 존재하지 않는 파일 경로, 예전 CLI 옵션, 삭제된 workflow, 최신 모델의 기본 행동과 중복되는 일반론이 계속 남는다.

문제는 지침이 보통 추가만 되고 삭제되지 않는다는 것이다.

## 2.4 모델이 좋아지면 오래된 scaffolding이 방해가 된다

초기에는 유용했던 세세한 레시피가 최신 모델에서는 오히려 유연성을 떨어뜨릴 수 있다.

모든 작업 전에 긴 계획을 요구하거나, 모든 변경에서 전체 테스트를 실행하거나, 모든 답변 끝에 동일한 자기 검증 체크리스트를 붙이게 하는 규칙이 대표적이다.

중요한 것은 최신 모델에는 지침이 필요 없다는 뜻이 아니다.

> 최신 모델일수록 프로젝트 고유 정보와 실제 위험 경계에 지침 예산을 더 집중할 수 있다.

## 2.5 Instruction Diet

지침을 줄일 때는 무조건 짧게 만드는 것이 목적이 아니다.

삭제 후보는 행동을 바꾸지 않는 설명, 다른 파일의 반복, canonical source에서 읽을 수 있는 값, 모델 기본 행동과 중복되는 일반론, 과거 workaround, 지나치게 넓은 trigger booster다.

유지해야 할 것은 프로젝트 고유 불변식, 코드만 보고 알기 어려운 사실, 위험한 side effect의 경계, 반복 실패 조건, 완료를 증명하는 기준이다.

## 2.6 좋은 상시 컨텍스트

좋은 상시 컨텍스트는 저장소를 빠르게 이해하게 하고, 올바른 세부 문서로 라우팅하며, 프로젝트 전역 불변식을 알려준다. 특정 업무 절차를 직접 품지 않고 자주 바뀌는 사실을 복제하지 않는다.

전역 지침은 백과사전이 아니라 **내비게이션과 불변식의 압축본**에 가깝다.
